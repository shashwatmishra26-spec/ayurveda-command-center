# Ayurveda Command Center

**A one-screen AI operations platform for an Ayurvedic clinic** — patient
management, a WhatsApp AI agent, an Ayurveda knowledge copilot, appointments,
medicine inventory, order & shipment tracking, follow-ups, and business
intelligence, unified behind one human-in-the-loop design: the AI drafts,
the Vaidya (practitioner) decides.

**Live demo:** https://shashwatmishra26-spec.github.io/ayurveda-command-center/

> All data in the live demo is synthetic/demo data, clearly labeled as such
> throughout the app — no real patients, orders, or clinical information.

## What's inside

- **Command Center dashboard** — a morning briefing, 12 clickable KPI cards,
  an AI Priority Queue with plain-language reasoning for every item, and a
  live alert feed.
- **Patient 360** — full profile (Prakriti/Vikriti, chief complaints,
  adherence), a chronological timeline across consultations, orders,
  shipments and messages, plus a Patient Retention AI view (churn-risk /
  high-value / overdue flags with a suggested outreach message).
- **WhatsApp AI Agent** — an inbox that classifies every inbound message,
  shows the AI's interpretation and knowledge-base sources, and requires an
  explicit **Approve & Send / Edit / Ask More / Escalate** decision before
  anything reaches a patient. Includes a step-by-step clinical query workflow
  demo and a hard-stop red-flag escalation path for emergency language.
- **Ayurveda Knowledge Copilot** — a retrieval-style knowledge base (classical
  texts + clinic-approved documents) where every answer is labeled as
  Verified clinic knowledge, Classical source, General information, or AI
  inference — nothing is presented as a classical fact unless verified.
- **Appointments** — an AI booking agent that checks real slot availability
  and never double-books.
- **Follow-ups & Refills**, **Inventory + Replenishment Agent** (forecasted
  stockouts, draft purchase recommendations — nothing auto-orders),
  **Orders & Shipment Control Tower** (India Post/courier tracking, clearly
  labeled as demo/simulated, plus a post-delivery discrepancy workflow),
  **Feedback & Business Intelligence** (with a Business Copilot chat that
  answers with explainable reasoning), **AI Agent Control Center** (12 agents
  with status/success-rate/human-intervention metrics), a full
  **human-in-the-loop audit trail**, **role-based access** (switch roles live
  to see permissions change), **global search**, and an **Alert Center**.

## Tech notes

The live site's `index.html` is a small static shell that loads React 18
from unpkg (a public CDN) plus this repo's pre-built `dist/*.build.js`
files and `src/data.js` via plain `<script>` tags — no build step runs on
GitHub's side. Under the hood:

- **React 18**, loaded from unpkg at runtime for the live demo. A separate
  `npm run build:standalone` script produces a single fully self-contained
  HTML file with **React 19 bundled in** (via esbuild, no CDN calls at all)
  for offline use — see "Running locally / editing" below.
- Hand-rolled **SVG charts** (no charting library dependency).
- **Tailwind CSS** via CDN for styling, with a small first-party fallback
  engine (`src/fallback-utils.js`) that re-applies the same utility values as
  inline styles if a CDN is unreachable, so the app still renders correctly
  offline (used by the standalone build).
- ~130 synthetic patients, medicines, orders, shipments, WhatsApp threads,
  etc., generated by a seeded random data engine (`src/data.js`) so every
  page load is internally consistent.

See [`ARCHITECTURE.md`](./ARCHITECTURE.md) for the full data model, entity
relationships, clinical AI guardrails, and notes on turning this prototype
into a real production SaaS (swapping the mock data layer for the WhatsApp
Business API, a calendar API, a courier tracking API, a payment gateway, and
a real LLM).

## Running locally / editing

The shipped `index.html` + `dist/` work as-is — serve the repo root with any
static file server (e.g. `npx serve .`) and open `index.html`, or just open
it directly in a browser. To modify the source and rebuild:

```bash
npm install
npm run build              # bash build.sh -> writes dist/*.build.js
npm run build:standalone   # also produces standalone.html (single self-
                            # contained file, React 19 bundled, no CDN calls)
```

Source lives under `src/` (`ui.jsx` = design system/primitives,
`modules1-3.jsx` = feature areas, `app.jsx` = shell/routing, `data.js` = the
mock data layer).

## Deploying your own copy

This repo is set up for **GitHub Pages**: Settings → Pages → Deploy from
branch `main`, folder `/ (root)`. `index.html` and the built `dist/` files
are committed to the repo, so that's the entire deployment — no build step
runs on GitHub's side; the page loads React from unpkg at runtime.
